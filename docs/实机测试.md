# 0.4.30 振动提醒独立开关（实体设备待测）

# 0.4.29 小窗动画取景边界（实体设备待测）

# 0.4.28 复制问题信息（实体设备待测）

- 在处理过暗、权限、相机占用或检测故障时，展开完整预览并找到「复制问题信息」，复制后粘贴到自己的文本编辑器，核对版本、型号、阶段和原始原因；时序属于事件当时的回调记录，不能当成真实相机端到端延迟。
- 故障后暂时切到后台，再回到同一预览页，检查离屏提示不覆盖首因；检测暂停后若预览也停止，报告应保留两类事件。此项不通过停止或返回操作结束 Activity，结束页面后不承诺保留报告。重新尝试预览后旧报告清除，主动重开检测后旧检测记录清除。
- 页面重建后报告标为保留记录，相机仍需主动开启；复制过程不应改变相机、声音、振动和会话。Android 13+ 使用系统复制确认，旧设备显示应用 Toast。
- 大字体、分屏、横竖屏和 TalkBack 下检查复制按钮可达、描述清楚；真实厂商剪贴板/权限返回行为与实际故障仍待验收。应用无响应、被系统杀死且未保留页面状态时不保证能生成报告。

- 在系统 100%/150%/200% 字体下检查小窗“未检测 / 仅预览”完整可见；使用 TalkBack 检查故障提示只在状态变化时朗读，避免每帧重复。系统朗读尚无设备结果。

检查 `PREPROCESS_PARITY_PASS`、`MODEL_PARITY_PASS` 和 `RUNTIME_PROBE_PASS`。探针对照保留在测试源码中的 0.4.8 预处理：14 组交替尺寸、颜色与透明度逐字节比较 RGB，检查缓冲区位置重置和源图所有权；人像/黑图/白图/重复人像用实际内置模型比较四组共 151 个浮点输出（误差不超过 1e-6），检查先前交付的结果不被后续推理改写。重复关闭和关闭后拒绝使用也在真实 Android 对象上检查。

`PREPROCESS_ALLOCATION_OBSERVATION` 是预热后 3 轮共 90 帧的有限观察：通过 ART 的进程级 managed bytes allocated 比较旧/新预处理，不包含 native 位图内存，不是线程独占数据，不据此宣称真实耗电/帧率或端到端延迟改善。

PiP 探针在确认默认检测/声音关闭后，主动开启基础识别并等待真实模型结果多次推进，关闭时检查 Ticket 与反馈取消，重新开启后等待新结果；实际小窗与展开后继续检查分析推进。息屏/停止时同时检查识别与旧反馈清空，唤醒后的新会话仍默认关闭检测。

首次开启还检查“正在准备识别器”状态，准备时不持有相机采样，模型就绪后才开始新帧推理。关闭时清空就绪/已分析标记；准备完成不延长原来的分析截止。`analysis-timing.txt` 保留模型初始化和慢画面复制耗时元数据，不含图像。

CI 每套模拟器执行两轮完整 PiP 探针，分别保存 `pip.txt` 与 `pip-repeat.txt`，均须包含 `PIP_PROBE_PASS`；同时保留 crash buffer、系统生命周期/进程日志和阶段计时。历史一次 Android 36 进程退出未取得堆栈，不能只凭重跑成功视为已修复，详见[验证记录](验证结果.md)。

每轮在真正 Camera2 LIVE 后包装实际 TextureView 监听器，在它的绘制更新回调中将采集心跳设为过期，再调用原业务监听。检查故障遮挡与相机/待处理任务释放、旧 View 在回调返回后从父节点移除、Activity 没有崩溃且可手动重开。这是仪器测试注入的截止场景，不是声称设备自然发生了相机故障。

唤醒并手动重开后，还直接调用内部接收器重放一次息屏通知，确认亮屏且解锁的新会话不被停止；这不是从系统发送受保护广播。真正的 KEYCODE_SLEEP 流程继续检查相机和待处理任务关闭。

| 实机补充场景 | 预期 | 结果 |
|---|---|---|
| 连续基础识别 10/30/60 分钟 | 记录堆内存、GC、真实端到端延迟和发热，不以模拟器分配数据替代 | 待测 |

记录设备型号、Android/API、厂商版本、电量、亮度、刷新率、温度、相机位置、系统电池策略。建议至少 Android 8、12、14、15、16 各一台/模拟器；模拟器只能验证 UI/部分生命周期，不能替代自然握持、真实视野、延迟/耗电测试。

## 第一阶段：先验证观察画面

1. 原地自然握持（通常看手机姿势）面对不同身高的陪同人员和软箱，记录后置镜头可视区域是否主要是地面、被手指遮挡或偏离前方。分别竖屏/横屏、左右手、不同握持角度。若视野不足，记录为失败，不以识别准确率替代。不得为看镜头而改变步态。
2. 在封闭场地缓慢正常步行，陪同人员记录前方 1/2/3/5m 的人/软箱是否进入画面。距离只由测试人工测量，应用不估计距离。
3. 启动后切换桌面、浏览器、文档、地图（非实际导航），每个持续5分钟；画面持续、停止按钮有效。遇使用 hideOverlayWindows 的 App，应记录浮窗被隐藏的系统限制；不要求绕过。停止后确认系统摄像头指示消失。
4. 标题拖动到四角，右下角缩放到最小/最大，旋转屏幕，确保停止与识别按钮可见，浮窗外能操作其他 App，比例和方向正确、不镜像。特别验证宽高比与模型旋转方向；实机未确认前不能宣称正确。
5. 真实端到端延迟：固定另一设备显示毫秒计时器/LED，用高速摄像把现实计时器和手机浮窗同时拍下，逐帧计算时间差。采样至少30组，记录 P50/P95/最大；检查可见跳帧。浮窗“帧龄”是回调到当前的年龄；首页“抽帧到结果”含模型初始化/推理/回调，均不等于真正镜头到屏幕延迟。没有高速设备时用秒表视觉比较，仅标明粗测误差。
6. 耗电：固定亮度、温度和应用前台场景，各跑基线（无摄像头）、只预览、预览+识别、预览+识别+声音各30分钟，至少三轮；记录电量变化/分钟、热状态、帧率、是否被系统限制、CPU。可选 `adb shell dumpsys batterystats --reset`，测试结束 `adb shell dumpsys batterystats com.cyanrbt.walkbuddy` 和 `adb shell dumpsys thermalservice`。不从 APK 或模型官方 benchmark 推断本机耗电。

## 故障与状态覆盖

每例记录出现时间、遮挡时间、相机指示、提醒是否静默、资源释放、重新开启是否需主动操作。

| 场景 | 期望 |
|---|---|
| 摄像头拒绝/不再询问；overlay 拒绝 | 首页明确未开启，不能打开相机；授权后仍需手动开启 |
| 通知拒绝 | FGS 依系统规则运行；浮窗仍有停止；通知可能不在通知栏显示，记录系统表现 |
| 连点开启20次、停止20次、启停交替 | 无重复窗口、旧回调不能复活、无闪现旧帧/资源泄漏 |
| 识别默认关闭、关闭再开启、声音默认关闭 | 关闭期间无推理/震动/声音；旧识别结果不得触发；每次启动均关闭 |
| 其他相机 App 抢占 | 明确不可用、遮挡并移除 TextureView、停止提醒、关闭 camera/session/surface；不后台抢回 |
| 锁屏/息屏 | 明确停止、相机资源释放；解锁不自动恢复 |
| Android 12+ 相机隐私开关 | 开启阻断后立即不可用；近纯黑保守检查及 OEM 行为需测；黑/占位回调不能被误称有效环境画面 |
| 运行中撤回 CAMERA/overlay | 可能系统杀进程；浮窗消失或显示不可用，通知/重进页不自动启动 |
| Surface 销毁、旋转、相机服务中断 | 销毁/中断不可用；最后一帧移除；旋转不得丢失停止入口 |
| 持续采集但不再显示、显示但采集 timestamp 不进展 | 1200ms 阈值后遮挡/释放；不能只靠一个心跳 |
| 分析线程阻塞/过慢 | 开启识别后1500ms无有效结果，遮挡画面+静默；晚结果丢弃；不排队 |
| 系统 FGS 管理器停止、force-stop/杀进程 | 浮窗消失；重新进入已停止，无后台恢复 |
| UI 主线程卡住 | 记录未保证及时遮挡；这是已知限制，不能据此宣称安全 |
| 长时间停止与反复恢复（50轮） | dumpsys media.camera 不再持有；内存/线程数量不持续上涨 |

开发调试可使用 Android Studio 断点暂挂 capture 回调、显示回调、LocalDetector，分别触发超时；断点不得把主线程挂起作为证明 watchdog 有效的方法。单元测试已覆盖纯状态逻辑，不能替代 camera/窗口系统集成测试。

## 第二阶段：识别实验

先通过第一阶段。由用户在浮窗勾选辅助识别，只在白天、正常步行、封闭场地测人、自行车、汽车、摩托车、公交车、卡车、椅子、长凳。不把照片或模型类别输出当作可靠环境识别。

每类至少30次不同朝向/遮挡/光照（不含夜间），人工记录 TP/FP/FN、误提醒每分钟、漏提醒、采样耗时 P50/P95、是否进入中央区域。person=人，不等同正在行走的行人；交通工具可能停靠且不挡路。中央区域和阈值只实验筛选，震动说明“潜在目标”，没有提醒不代表安全。坑洞/台阶/玻璃/细杆/墙面无支持承诺。先原地开启识别，看到耗时稳定再做封闭场地步行测试。

模型错误、画面过暗、采集/分析过期期间不能提醒。注意声音不会绕过静音/勿扰策略。不要用 app 的缺失提醒来决定前进。
