更新：0.4.0 已改为优先使用不依赖语义类别的[空间检测](空间检测.md)。以下为此前的类别模型调研记录，候选权重没有集成。基础模式已取消八类筛选；空间模式按几何区域判断，仍需实机验证。

用户目标：OPPO Find X8 Ultra，竖屏胸前持机，识别人（包括儿童）、车辆、锥桶/围挡、上下台阶；坑洞单独研究。

## 2026-10-30 实际文件与推理核验

本轮交付为隔离研究工具，生产 APK 仍为 0.4.18。下表保留早期线索；候选模型卡的宣称与实际文件核验分开记录，新增类别尚未交付。

## 模型接入和验收条件

1. 每份权重固定来源版本、SHA-256、精确类别顺序、输入输出约定与许可/署名。预处理、量化和NMS必须匹配该权重。
2. 台阶分别标注上行、下行；单级路沿与多级楼梯均纳入。儿童仍归person，在评价中按目标大小、遮挡程度分组，不做年龄判断。
3. 从胸前步行视角覆盖人车、各色锥桶、塑料/金属围挡、上/下台阶，以及条纹地砖、斑马线、阴影等负例。同一路线/视频的相邻帧必须留在同一数据划分，避免训练测试泄漏。
4. 对每类记录漏检、误检、框重叠、首次提示时机、每分钟误提醒；测试近/远、小目标、遮挡、逆光和持机倾斜。通过标准必须先于测试确定，不能测试后挑阈值报好成绩。
5. 在指定手机测冷启动、稳定推理时延、连续运行热衰减及PiP帧龄。计算速度和识别质量分别验收。没有输出不能显示“安全”。
6. 坑洞/落差另设数据与验收，不从单张相对深度图推断可靠的米制距离或宣称能覆盖深坑。

无实机和标注测试集时，只能完成代码与张量契约验证，不能验收真实道路识别能力。


## 继续核对的宽松许可线索

已实际下载 Google 发布的 Open Images V4 SSD MobileNet V2 v1（API 标明 Apache 2.0），校验归档与 SavedModel 后执行宿主参考推理；真实模型的台阶 MID 为 `/m/01lynh`、数字标签为 93。模型卡的两个字符串输出字段与真实文件相反，已按真实契约读取并加入回归测试。

从固定验证集在推理前排序选取的三张照片中，仅一张在 0.35 分数下产生台阶框，且与标注最大 IoU 约 0.287；其余两张没有达到该分数的台阶框。该小样本不能估计总体精度，也不能验证胸前步行视角或上/下方向。完整来源、照片署名、原始结果与[复现记录](profiles/openimages-stairs-2026-10-30.md)已保存。尚未转换 TFLite、接入 Android 或验收手机性能，生产 APK 仍使用原基础模型。
