# WalkBuddy 0.4.9

ARM64 调试包，最低 Android 8；versionCode 21，包名与固定发布签名保持不变。

- 开启检测先显示“正在准备识别器”，在唯一 worker 完成模型初始化后才采样新帧，避免图片在初始化期间变旧；准备过程仍计入原有 1500ms 分析截止。

- 基础识别为每个识别器复用 320×320 预处理位图、像素数组、RGB 直接输入和四组直接输出缓冲区，减少持续分析时的大块分配。
- 每帧完整清理预处理画布，切换横竖画幅、透明图像时不保留上一帧的边缘；检测结果采用独立副本，后续推理不改写已经显示的内容。
- 过期图像及结果仍丢弃；会话仍有效时保留已经就绪的模型供新帧使用，避免反复加载。会话过期、取消、故障或更换所有者仍串行关闭模型，不增加并行识别器，不改变提醒阈值及任何截止时间。
- 推理 worker 在创建模型前设置 Android 后台线程调度，减少与界面、相机和渲染竞争；仍受原有分析截止保护。
- 修复故障停止时可能退出的问题：立即遮挡、关闭相机和取消提醒，在当前绘制返回后再移除取景 View；图像读取也移到绘制结束后，避免纹理层重入。
- Android 15/16 检查新增逐字节 RGB 对照、真实模型全部输出对照和有限场景的分配量观察；每套模拟器运行两轮实际 Camera2/PiP 识别，检查准备状态、分析推进、关闭重开和停止清理。

模型、类别及评分规则没有更换。分配量优化不等于设备帧率、耗电或识别准确率改善；实体后摄、TalkBack、AR 深度及 OEM 行为仍需设备验收。本应用不保存或上传画面；CI 测试人像仅在测试 APK 中，虚拟相机截图也仅由测试工具生成。没有提醒不代表安全，路仍要自己看。

问题定位、原始分配观察与回归范围见[验证记录](https://github.com/cyanrbt/walkbuddy/blob/v0.4.9/docs/验证结果.md)。
