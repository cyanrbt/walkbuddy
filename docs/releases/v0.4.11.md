# WalkBuddy 0.4.11

ARM64 调试包，最低 Android 8；versionCode 23，包名与固定发布签名保持不变。

- 识别取样按模型所需尺寸直接读回：保留天然画幅比例，长边最多 320 像素，再补偿显示方向。当前 640×480 相机流的单张采样位图由 1,228,800 字节降为 307,200 字节；屏幕预览分辨率和相机流尺寸保持不变。
- 缩放路径调整后继续使用原模型和阈值；显示与分析不拉伸。输入及结果新鲜度、采集/显示/分析截止维持原值。
- 实时识别 worker 调整为略低于主线程的优先级 1，在创建模型前应用；同机 10→1→1→10 对照中，优先级 1 的四轮均通过，10 的四轮有一轮分析截止。初始化耗时仍有波动，正式默认配置已另跑完整回归。
- 位图读回发生运行时异常时，进入原有停止与手动恢复流程；旋转失败释放中间位图。
- 故障时记录采集/显示/分析间隔、取样排队与复制耗时、结果回到主线程的等待时间；慢推理增加 worker 自身 CPU 时间，便于继续区分超时来源。记录仅含计时元数据。
- CI 新增 32 组原生 TextureView/Surface/PixelCopy 方向检查，对照旧读回方法的位图大小与有限场景耗时；保留实际虚拟 Camera2/识别/PiP 两轮检查。

135 项 JVM 测试、Lint 无错误与应用/测试包构建通过。[Android 15/16 正式配置检查](https://github.com/cyanrbt/walkbuddy/actions/runs/40898307142)首次运行均成功，各含 32 组真实纹理方向/比例检查及两轮完整虚拟 Camera2/识别/PiP。对照、失败与计时范围见[验证记录](https://github.com/cyanrbt/walkbuddy/blob/v0.4.11/docs/验证结果.md)。旧版 CI 的间歇性超时原因尚未全部定位，本版不以缩小位图等同于已修复所有超时，也不宣称实体设备帧率、耗电或识别准确率提升。
