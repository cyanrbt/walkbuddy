# WalkBuddy v0.4.38

亮度检查在观察到实际更新时尽早投递独立线程，默认仅预览不再为亮度额外排队主线程读回任务；主线程只包装 Surface，像素复制与求和在 worker 完成。检测开启后的模型取样继续在绘制结束后执行。

保留原观测时间、暗画面阈值、每秒检查间隔和全进程单飞。包装/投递后按当前时钟再检查健康，采集/显示 1200ms、亮度请求从最早到期帧起 1000ms 及分析截止保持；错误或超时停止预览，仍需主动重新开启。旧 TextureView 的迟到回调不会影响新观察，退休复制完成后再回收其缓冲。

问题信息单独记录亮度等待、复制、交付阶段与结果码，保留首个事件和页面重建信息，不保存图像。当前为未发布候选；[本轮验证](https://github.com/cyanrbt/walkbuddy/blob/perf/brightness-async-a110908/docs/profiles/brightness-early-queue-2026-10-31.md)区分本地、绘制内实际复制、像素对照、真实虚拟 Camera2 恢复和正式包。仍可能有共享渲染线程等待，不宣称历史停顿根因解决或实体性能改善。实体设备、真实 AR、TalkBack 与道路体验仍待验收。
