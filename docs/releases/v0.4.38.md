# WalkBuddy v0.4.38

亮度检查在观察到实际更新时尽早投递独立线程，默认仅预览不再为亮度额外排队主线程读回任务；主线程只包装 Surface，像素复制与求和在 worker 完成。检测开启后的模型取样继续在绘制结束后执行。

保留原观测时间、暗画面阈值、每秒检查间隔和全进程单飞。包装/投递后按当前时钟再检查健康，采集/显示 1200ms 与原分析截止保持；超过 1000ms 的旧观测不启动新请求，异步亮度请求新增最早到期帧起最多 1200ms 的有界等待。错误或超时停止预览，仍需主动重新开启。旧 TextureView 的迟到回调不会影响新观察，退休复制完成后再回收其缓冲。

问题信息单独记录亮度等待、复制、交付阶段与结果码，保留首个事件和页面重建信息，不保存图像。

259 项 JVM、Android 8/15/16 像素专项及 Android 15/16 系统轨迹候选检查均首次通过，五份原始附件、六条实际轨迹已下载核验重放。[本轮验证](https://github.com/cyanrbt/walkbuddy/blob/main/docs/profiles/brightness-preview-budget-2026-10-31.md)区分本地、绘制回调内复制、真实虚拟 Camera2 恢复与实际 APK。固定签名 ARM64 APK 由本版本标签流程在两套 Android 检查通过后构建发布；正式资源与构建结果另行核验。

仍可能有共享渲染线程等待，不宣称历史停顿根因解决或实体性能改善。实体设备、真实 AR、TalkBack 与道路体验仍待验收。

[正式构建 41172338591](https://github.com/cyanrbt/walkbuddy/actions/runs/41172338591) attempt 1 的两套 Android 与 APK 均成功，Release 实际存在 [ARM64 APK](https://github.com/cyanrbt/walkbuddy/releases/download/v0.4.38/Walk-Buddy-v0.4.38-arm64-debug.apk)。实际 9,996,881 字节包已下载核对固定签名、版本、模型及服务端摘要，正式 UI 两份原始附件已核验重放。[安装包验证](../profiles/apk-v0.4.38.json)保留；开发专项中的不同失败不回写为通过。
