# 中文界面与完整技术方案

名称“Walk Buddy”，版本0.2.4，面向个人学习交流。0.2.4 重画启动图标并收起悬浮窗控件，观察与识别行为仍按下文。首版只考虑白天正常步行观察实验，主要由用户观察后置画面，不能把提醒当作安全判断；可能误报漏报，没有提醒不代表安全。

首页：用途/限制、摄像头权限、悬浮窗权限、通知权限、主动开启、停止、当前状态、采集/显示帧龄与抽帧到结果耗时。浮窗：标题拖动、实时后置画面、故障黑色遮挡、辅助识别勾选（默认关闭）、声音勾选（默认关闭）、停止、右下角缩放。故障不自动恢复，用户回可见首页主动再次开启。

## 原生Java路线与固定依赖

Activity、Service、Camera2和状态/调度均用Java17，方便Java后端用户阅读。Groovy Gradle和XML仅用于构建与平台配置。当前不采用MediaPipe高层封装；使用LiteRT Java Interpreter直接核对精确模型的输入输出、字节格式与标签，减少不必要运行依赖，避免把不同权重视作兼容。

交付APK默认ARM64-only（arm64-v8a）；最低Android8/API26，compile/target36；源码用-PuniversalApk可恢复arm64-v8a/armeabi-v7a/x86/x86_64通用构建。Gradle8.13、AGP8.10.1、Build Tools36.0.0、OpenJDK17.0.13+11、LiteRT/litert-api1.4.0固定，JUnit4.13.2只用于测试。Gradle wrapper有官方摘要；依赖锁固化间接版本。640×480后置流不支持时明确不可用；CPU2线程推理，约2Hz抽帧，推理忙则不抽取/排队新帧。

## Android平台要求与生命周期

- 可见Activity且CAMERA已授权后才主动启动camera前台服务，及时startForeground，然后打开相机。服务持有camera/session/surface；跨App不依赖Activity生命周期。
- 声明CAMERA、SYSTEM_ALERT_WINDOW、FOREGROUND_SERVICE、FOREGROUND_SERVICE_CAMERA、POST_NOTIFICATIONS、VIBRATE；最终合并APK无INTERNET/ACCESS_NETWORK_STATE/录音/存储权限。
- Android12+限制后台启动FGS；14+创建camera服务检查while-in-use CAMERA；15+一般悬浮窗FGS豁免也要求已有可见overlay。overlay权限不是后台启动相机的通用豁免。
- START_NOT_STICKY，不开机/后台自动启动、不后台抢回相机。锁屏进入不可用并释放相机；系统杀进程时自身浮窗消失，重进只显示已停止。
- 其他App可隐藏悬浮窗，不能保证所有App可见。仅浮窗真实边界接收拖动/缩放，不用透明全屏窗口，旋转后限制到屏幕内。
- 停止/销毁显式cancel通知ID1，包括已detach的故障通知。

## 可审查状态机与截止锁存

STOPPED→STARTING→LIVE；任何故障/截止→UNAVAILABLE；停止→STOPPED。重复开启不重建窗口，重复停止安全；故障只允许通过可见页主动恢复。

所有状态变化在service主线程。摄像头回调带session generation；识别每次启停另换Ticket和epoch。旧会话/旧识别结果不得改变当前UI或提醒。

启动5秒还无采集+显示心跳不可用。采集SENSOR_TIMESTAMP必须递增，显示通过TextureView.onSurfaceTextureUpdated独立更新；任一心跳1200ms过期即失败。REALTIME来源才比较SENSOR_TIMESTAMP与elapsedRealtimeNanos；UNKNOWN只检查本会话时间戳进展。不用相同像素判断冻结。

采集、显示回调、晋升LIVE以及分析结果提交前，都先检查并锁存已过deadline，不允许迟到回调抢在100ms watchdog前续写旧心跳。识别开启后1500ms没有有效分析结果不可用；抽帧到提交超过1000ms丢弃。失败先不透明遮挡并移除TextureView，释放camera/session/surface，取消震动/声音、推理Ticket及待处理帧。UI主线程卡死无法保证及时绘制故障，阈值还存在调度延迟。

## 唯一worker与取消/资源生命周期

进程静态共享一个InferenceWorker，service反复启停不创建更多worker；最多1个待处理帧。UI仅在worker不忙时采样。拒绝、取消排队帧、完成或失败均恰好释放Bitmap一次；不保存图像。

Ticket包含volatile取消标志与采集/显示/分析心跳。模型创建前、创建后/native调用前、结果排主线程前再次检查取消和帧deadline；主线程提交时再检查generation/epoch、画面新鲜度及分析deadline。取消会立即清掉排队帧和结果回调引用；模型创建/推理/关闭串行且不持调度锁，不让停止入口等待native操作。

已进入native推理/初始化的任务不能承诺立即中断：其输入及native资源须等调用返回才释放。期间相机画面仍按状态机不可用、提醒静默；同一worker不并发创建替代解释器，阻塞永不返回时后续识别将超时不可用，不能通过不断启停堆积worker。7项阻塞fake回归验证取消、工厂超时、排队过期、100次重启、失败恢复与close不阻塞取消；不能把fake测试当成证明native一定会返回。

## 精确模型、预处理与实际支持

TensorFlow EfficientDet Lite0 detection metadata v1，官方实例992/versionId1146，SHA256 `2e04c53bfeac0ac2a30c057c7e2a777594ce39baaac35a92f74fb1e8c4fc4e0b`。官方发行JSON和内嵌元数据均明确Apache2.0；与此前移除的MediaPipe权重是不同文件，不能沿用旧摘要。

UINT8 RGB输入[1,320,320,3]，像素0..255；保持比例letterbox为320×320，系统补偿传感器方向后只补偿显示旋转，在输出框筛选前反算padding。Interpreter分配后逐项校验4个FLOAT32输出：[1,25,4]框、[1,25]类别、[1,25]分数、[1]数量。静态文件输出shape为空，实际分配shape已在Android模拟器验证，不能只看静态schema猜测。

labelmap为90槽（80COCO类，含???空槽），person索引0。当前allowlist只选人、自行车、汽车、摩托车、公交车、卡车、椅子、长凳。模型可输出其他类，但不会用它们提醒。阈值0.6、中央横向20%～80%、框下沿35%以下区域是未标定经验筛选，不计算物理距离/深度或真实路径；person也不等同正在行走的行人。

两次相同支持类别、间隔≤1200ms才提醒，至少3秒冷却；震动150ms，声音需另外主动勾选。关闭识别、画面/分析过期、故障/停止即静默。玻璃、坑洞、台阶、细杆、墙体等不覆盖，目标分数不是安全概率。

## 隐私与已知边界

Android12+相机隐私开关可能持续返回占位画面；本代码不调用隐藏状态查询/监听。每秒保守检测近纯黑画面（仅白天，可误停），并处理camera错误；无法保证识别全部OEM非黑占位、屏幕合成冻结或镜头朝向错误。心跳不证明光学环境有效。

默认不保存、不上传，只有内存Bitmap，处理后释放；没有画面日志、运行网络权限、云推理或模型运行时下载。构建依赖下载不属于画面上传。自然握持视野、真实端到端延迟、耗电/热表现与实机效果未测。帧龄和抽帧结果耗时不等于真实相机到屏幕延迟。
