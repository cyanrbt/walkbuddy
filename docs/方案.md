# 中文界面与完整技术方案

名称“Walk Buddy”，版本0.4.11，面向个人学习交流。默认使用系统画中画（PiP）显示后置摄像头实时预览，不申请特殊悬浮窗权限。首版只考虑白天正常步行观察实验，不能把提醒当作安全判断；可能误报漏报，没有提醒不代表安全。

首页底部主要操作独立于滚动正文，跟随权限和预览状态显示授权、打开或返回预览；仅启动/实时期间显示停止。返回已有预览复用 Activity，故障/停止后仍需手动恢复。无预览时不进行周期刷新，在恢复前台和窗口重新获得焦点时同步状态。

首页：用途/限制、摄像头权限、画中画可用状态及系统设置入口、打开预览、停止、当前状态。完整预览页：实时画面、故障黑色遮挡、辅助识别和声音（每次开启默认关闭）、以小窗观察、停止、故障后的主动重新开启。小窗显示画面、检测框、持机姿势提示/故障遮挡，系统菜单提供停止和返回完整界面。画中画不支持、被禁用或进入失败时保留应用内预览，不使用特殊悬浮窗兜底。

## 原生Java路线与固定依赖

Activity、Camera2和状态/调度均用Java17，方便Java后端用户阅读。Groovy Gradle和XML仅用于构建与平台配置。当前不采用MediaPipe高层封装；使用LiteRT Java Interpreter直接核对精确模型的输入输出、字节格式与标签，减少不必要运行依赖，避免把不同权重视作兼容。

交付APK默认ARM64-only（arm64-v8a）；最低Android8/API26，compile/target36；源码用-PuniversalApk可恢复arm64-v8a/armeabi-v7a/x86/x86_64通用构建。Gradle8.13、AGP8.10.1、Build Tools36.0.0、OpenJDK17.0.13+11、LiteRT/litert-api1.4.0固定，JUnit4.13.2只用于测试。Gradle wrapper有官方摘要；依赖锁固化间接版本。640×480后置流不支持时明确不可用；CPU2线程推理，约2Hz抽帧，推理忙则不抽取/排队新帧。

## Android平台要求与生命周期

- 最低 Android 8/API26。先检查 `FEATURE_PICTURE_IN_PICTURE` 和应用画中画 AppOp，再处理进入失败/系统拒绝；入口失败不关闭当前预览。
- `PreviewActivity` 声明 `supportsPictureInPicture`、`singleTask` 和尺寸/方向配置变化处理。仅用户在可见完整预览中明确点击后进入 PiP，不因切换其他页面自动进入。
- 相机和 Surface 归预览 Activity 管理；PiP 仍是可见 Activity，不使用相机前台服务。`onPause` 不释放相机；`onStop` 无条件停止采集（包括关闭 PiP 时仍报告处于 PiP 的情况）。锁屏广播同样停止，不后台抢回相机。
- 配置变化和进入/退出 PiP 保留同一预览 Surface，只重算显示变换和取消旧识别结果。进程/Activity 重建不自动打开摄像头，需再次主动开启。
- 权限仅 CAMERA、VIBRATE；无 SYSTEM_ALERT_WINDOW、FOREGROUND_SERVICE、FOREGROUND_SERVICE_CAMERA、POST_NOTIFICATIONS，也无网络/录音/存储权限。
- 拖动、尺寸和关闭由系统管理。PiP 隐藏完整页面按钮，通过 RemoteAction 停止；返回完整页面后配置识别、声音。声音仅在识别开启时可用。
- 故障先遮挡最后一帧并释放相机，停止提醒；小窗内不能后台重启，只能回完整预览页主动恢复。

## 可审查状态机与截止锁存

STOPPED→STARTING→LIVE；任何故障/截止→UNAVAILABLE；停止→STOPPED。重复开启不重建窗口，重复停止安全；故障只允许通过可见页主动恢复。

所有状态变化在预览Activity主线程。摄像头回调带session generation；识别每次启停另换Ticket和epoch。旧会话/旧识别结果不得改变当前UI或提醒。

启动5秒还无采集+显示心跳不可用。采集SENSOR_TIMESTAMP必须递增，显示通过TextureView.onSurfaceTextureUpdated独立更新；任一心跳1200ms过期即失败。REALTIME来源才比较SENSOR_TIMESTAMP与elapsedRealtimeNanos；UNKNOWN只检查本会话时间戳进展。不用相同像素判断冻结。

Camera2 的 REALTIME 元数据若提前返回，最多允许等待 33,333,334ns（一个 30fps 帧周期）；等待期间不刷新采集心跳，到时间后重新检查原会话、所有截止时间和时间戳年龄。验收时仍采用最初收到回调的时刻作为心跳，不能以等待完成时间延长有效期。主线程最多保留一个待校验的元数据任务，不持有图像；停止/故障关闭相机时取消，旧 generation 回调忽略。超过等待预算、已经过期或无效的时间信息仍停止预览。AR 深度后端不经过此 Camera2 规则。

采集、显示回调、晋升LIVE以及分析结果提交前，都先检查并锁存已过deadline，不允许迟到回调抢在100ms watchdog前续写旧心跳。识别开启后1500ms没有有效分析结果不可用；抽帧到提交超过1000ms丢弃。失败立即不透明遮挡、释放camera/session/surface、取消震动/声音、推理Ticket与待处理任务，并断开取景业务引用/监听；实际移除旧 TextureView 排到下一条主线程消息，避免在它自己的绘制回调中销毁当前纹理层。UI主线程卡死无法保证及时绘制故障，阈值还存在调度延迟。

亮度检查和模型图像读取不在 SurfaceTextureUpdated 的绘制回调中执行；合并为至多一个待执行的主线程读回任务。它保留原显示事件时刻、generation、识别 epoch 和取景 View 身份，执行时重新检查会话与帧龄，亮度读取后再次检查截止；不以任务执行时间冒充新显示。关闭相机取消待读回任务，换会话/换 View 的旧任务直接忽略。

尚未进入 LIVE 的启动阶段遇到旧元数据时只丢弃，不把它记为新采集；遮挡持续到新鲜采集和显示同时就绪，最初的 5000ms 启动截止保持不变。进入 LIVE 后仍按 1200ms 规则拒绝旧戳并停止。

## 唯一worker与取消/资源生命周期

进程静态共享一个InferenceWorker，预览反复启停不创建更多worker；最多1个待处理帧或准备请求。开启检测先在 worker 准备模型，不持有相机图像；UI 只在模型就绪且 worker 不忙时采样。准备仍计入最初的分析截止，不因就绪或重试重置时间。拒绝、取消排队帧、完成或失败均恰好释放Bitmap一次；不保存图像。

相机分析取样按天然画幅比例直接读到长边不超过 320 的位图，小窗尺寸不决定采样画幅，不放大更小的来源；显示方向仍只补偿一次。当前 640×480 流读回 320×240 或 240×320，单张位图像素量为原来的四分之一。主预览相机流仍为 640×480，模型和截止时间保持不变。

每个 LocalDetector 复用固定 320×320 的 letterbox 工作区（位图、Canvas、绘图参数、像素数组与 UINT8 RGB 直接输入），并使用四个原生字节序的 FloatBuffer 接收模型输出。准备新帧前完整涂黑画布并重置缓冲区的位置/容量，避免前一幅画面的边缘或消费者位置残留。结果中的类别、分数和 Detection 独立于工作缓冲区，后续推理不能改写已经提交的结果。关闭工作区回收预处理位图，输入帧仍归 worker 释放；取消时不在 UI 线程回收正在被 native 使用的数据。该复用仅减少识别预处理/输出分配，相机抽样 Bitmap 与结果对象仍可能分配，不代表整个应用零分配。

创建 Interpreter 之前把识别 worker 设为 Android `THREAD_PRIORITY_BACKGROUND`，降低推理与 UI/相机/渲染争用；CPU 推理仍使用两线程，所有采集/显示/分析截止维持原值。调度较低不保证推理始终及时，过载仍会不可用；通过实际开启识别的 PiP 探针验证运行，不用离线模型对照替代实时链路检查。

Ticket包含volatile取消标志与采集/显示/分析心跳。模型创建前、创建后/native调用前、结果排主线程前再次检查取消和帧deadline；主线程提交时再检查generation/epoch、画面新鲜度及分析deadline。取消会立即清掉排队帧和结果回调引用；模型创建/推理/关闭串行且不持调度锁，不让停止入口等待native操作。

图像单独超过 1000ms 时丢弃该图像/结果；若模型所属 Ticket 的采集/显示/分析心跳仍有效，可保留已经就绪的模型供新鲜图像使用。Ticket 过期、取消、模型错误或所有者不匹配仍关闭模型。保留模型不更新任何心跳，不接受旧输入，也不延长会话。

仅窗口几何变化时增加分析 epoch、立即释放排队旧帧并清除旧回调；沿用该相机会话的 Ticket 和模型，等待新几何下的图像，不因小窗动画重复加载权重。准备模型时发生几何变化也只通知最新回调。关闭检测、停止、模式/相机会话变化仍取消 Ticket 并释放模型。

已进入native推理/初始化的任务不能承诺立即中断：其输入及native资源须等调用返回才释放。期间相机画面仍按状态机不可用、提醒静默；同一worker不并发创建替代解释器，阻塞永不返回时后续识别将超时不可用，不能通过不断启停堆积worker。17项 worker/准备回归验证取消、工厂与帧截止、排队过期、准备失败、有效 Ticket 内复用、所有者隔离、100次重启与close不阻塞取消；不能把fake测试当成证明native一定会返回。

## 精确模型、预处理与实际支持

TensorFlow EfficientDet Lite0 detection metadata v1，官方实例992/versionId1146，SHA256 `2e04c53bfeac0ac2a30c057c7e2a777594ce39baaac35a92f74fb1e8c4fc4e0b`。官方发行JSON和内嵌元数据均明确Apache2.0；与此前移除的MediaPipe权重是不同文件，不能沿用旧摘要。

UINT8 RGB输入[1,320,320,3]，像素0..255；保持比例letterbox为320×320，系统补偿传感器方向后只补偿显示旋转，在输出框筛选前反算padding。Interpreter分配后逐项校验4个FLOAT32输出：[1,25,4]框、[1,25]类别、[1,25]分数、[1]数量。静态文件输出shape为空，实际分配shape已在Android模拟器验证，不能只看静态schema猜测。

labelmap为90槽（80 COCO 类，含 ??? 空槽），person索引0。基础模式显示所有非空类别、分数至少0.35的候选，灰色表示候选；分数至少 0.5、与横向 25%～75% 关注区相交且下沿超过画面 45% 时，经连续确认显示黄色并振动，注明未测距。分数不是危险概率；基础模式不从二维框大小推断物理距离。模型权重未更换，不宣称召回率已提高。

0.4.0新增可选 ARCore 1.56.0 深度后端，与 Camera2 互斥占用相机。几何障碍、地面确认、距离分级、连续确认及深度过期处理详见[空间检测](空间检测.md)。基础识别 worker 的截止规则保持；0.4.1 在增强模式也持续运行基础识别；深度失效只撤销测距轮廓，不清除新鲜的基础框和画面关注提醒。两个数据源独立确认与过期，输出合并，共用提醒冷却。空间检测不依赖类别名单。

## 隐私与已知边界

Android12+相机隐私开关可能持续返回占位画面；本代码不调用隐藏状态查询/监听。每秒保守检测近纯黑画面（仅白天，可误停），并处理camera错误；无法保证识别全部OEM非黑占位、屏幕合成冻结或镜头朝向错误。心跳不证明光学环境有效。

默认不保存、不上传，只有内存Bitmap，处理后释放；没有画面日志、运行网络权限、云推理或模型运行时下载。可选 AR 服务由 Google 提供，安装更新与服务数据处理独立于本应用；启用前展示服务隐私说明。构建依赖下载不属于画面上传。自然握持视野、真实端到端延迟、耗电/热表现与实机效果未测。内部心跳只能判断回调是否持续，不能当作真实相机到屏幕延迟。

## 0.3.1 可见反馈和姿势

所有候选保留归一化区域，映射到 PreviewGeometry 实际图像矩形。0.4.0基础模式用灰色/黄色角框；空间模式显示深度区域轮廓，灰/黄/红分别表示捕获、可能受阻、很近，黄红需连续确认。基础结果超过1秒、深度结果超过500毫秒清空；关闭检测、变换和停止均清空。PiP保留轮廓，空间模式也保留深度状态。
重力传感器优先，缺失时对加速度传感器低通滤波。设备Z轴的重力分量绝对值占比>0.75持续2秒时提示可能朝地面/天空；<0.60持续1秒恢复，间隔>1.5秒清空状态。提示不依赖识别开关，停止/销毁注销传感器，小窗同样可见。该规则不能判断朝向身后、遮挡、镜头实际视野；它也不改变物体检测结果。没有可用传感器时不提供自动姿势提示。目标实机是OPPO Find X8 Ultra，竖屏胸前；尚未实机标定角度和检测性能。
