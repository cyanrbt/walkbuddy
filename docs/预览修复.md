# 0.2.1 预览方向与比例修复

2026-10-10；versionCode 3，versionName 0.2.1。公开源码不含原调试密钥；本地或云端生成的调试 APK 签名可能不同，不能保证覆盖旧包升级。仅 ARM64，最低 Android 8.0/API 26。

根因：TextureView 的系统纹理已经补偿后置相机 SENSOR_ORIENTATION，旧代码再次叠加 sensor rotation，造成额外90度偏转。旧识别按640×480读取不同尺寸浮窗的内容，再次旋转，存在非等比采样和重复旋转。

PreviewGeometry 以固定且相机支持的640×480 buffer、sensor orientation、Display.getRotation与实际view尺寸计算矩阵。先还原系统默认铺满view的非等比缩放，只补偿负display rotation，再统一等比缩放居中，完整显示输入流，允许黑边，不裁切充满，不镜像。TextureView设为非opaque，父容器黑底。Surface尺寸改变、配置改变及DisplayListener（包含180度翻转）重算；重新开启重新计算。支持时显式关闭平台 SCALER_ROTATE_AND_CROP 自动裁切模式。

识别读取TextureView纹理时按系统传感器补偿后的天然尺寸读取，再仅旋转display一次。模拟器确认getBitmap没有包含view的fit-center Matrix；实际屏幕验证使用PixelCopy。采样方向与可见内容相同，模型继续保持比例letterbox。改变方向/尺寸时清除提醒、取消旧ticket，过期结果不可再提醒。旋转并不改变摄像头帧过期保护。

完整构建与26项单测通过：状态15、调度7、数学4。数学测试覆盖4种sensor×4种display×5种宽高、等比圆形、中心/边界、重开及尺寸变化。真实TextureView合成测试32组合（sensor 0/90/180/270×display 0/90/180/270×300×400及280×210），通过屏幕PixelCopy方向标记和圆形、识别输入方向及圆形比例。每组重建Surface；合成生产者模拟系统已补偿sensor的纹理，不等于验证32种实际相机HAL。测试PNG只保存在模拟器测试缓存，生产逻辑不保存画面，交付ZIP排除测试截图。

历史开发环境中实际 Android 模型人物与黑图测试通过，原调试签名 APK 安装/升级成功；不适用于本次云构建。lint 0错误、3警告：固定Gradle及LiteRT版本更新提示、ARM64-only缺少ChromeOS x86_64支持。签名、16KB zipalign、模型SHA256、ABI、权限检查通过，无联网权限。工具卡在macOS文件监听后以 --no-watch-fs 离线构建完成。
