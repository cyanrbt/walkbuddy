# 2026-10-30 单/双 CPU 线程对照

来源：[工作流 40994466003](https://github.com/cyanrbt/walkbuddy/actions/runs/40994466003)，源码 `194df38`。两套双核 x86_64 模拟器分别运行 2→1→1→2；每轮独立 instrumentation 进程，同一模拟器、nice 1、同一模型和截止时间。每轮执行完整相机/模型/PiP 场景。正常配置另有 [40994453588](https://github.com/cyanrbt/walkbuddy/actions/runs/40994453588) 完整原生回归，两套 API 均通过。

两套 API 的线程输出对照均通过：人像、黑图、白图、重复人像，每组全部 151 个浮点输出在 1e-6 内一致，确认主类别相同。四轮相机流程全部成功，未修改超时条件或删除失败轮次。

原始 `thread-summary.json` 分别保存为 [API 35](threads-2026-10-30-api35.json) 和 [API 36](threads-2026-10-30-api36.json)，包含每个 Interpreter 首次/后续推理、预处理和 worker CPU 的样本数、中位数与最大值。诊断实例记录每次完成的推理，避免只取慢调用；失败实例也会汇总。worker CPU 不包含辅助线程，native 墙钟不包含完整取样与结果交付，初始化样本包含首次开启和关闭后重开。

本次单线程多数轮次的 native 中位数较低，API 36 第二轮单线程高于第一轮双线程；不能宣称每轮更快。八轮均成功，因此不能证明超时率下降。0.4.15 仅在可用处理器不超过两个时选择单线程，更多处理器沿用双线程；采用该选择是根据双核配置的短实验减少并行争用，仍需长期观察。

该结果未覆盖 ARM64 真机、功耗、温升或实际物体准确率，不直接外推 Find X8 Ultra。参考 [LiteRT 性能建议](https://developers.google.com/edge/litert/conversion/tensorflow/build/best_practices)中关于多线程收益和并发波动的说明。复现实验可手动运行 `Inference thread profile`；正常发布工作流始终运行应用默认配置。
