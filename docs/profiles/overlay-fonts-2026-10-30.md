# 2026-10-30 取景标签字号与可读性

此前取景标签使用 11dp 绘字、固定的上下背景边界，系统大字体没有放大标签，字号改变也没有对应的字形空间。参考 [Lookout 对字体与外观调整的支持](https://support.google.com/accessibility/android/answer/9031274?hl=zh-Hans)所体现的阅读需求，并按 [Android 非线性字号建议](https://developer.android.com/about/versions/14/features#non-linear-font-scaling)使用系统 sp 转换；本项目不加入文字识别或 Lookout 服务。

## 改动

- 标签字号改为资源中的 11sp，经 Resources 获取像素，不手工乘 fontScale/scaledDensity；字体配置变化按原 Activity 重建规则使用新资源。
- 依据字体 top/bottom 与当前文本 getTextBounds 的更大范围计算背景和基线，四周保留 dp 留白。背景完整限制在实际相机图像范围内，包含留黑边的画面。
- 完整限定优先于对象尾部；若省略会破坏限定，则显示完整限定本身，测距可去掉空格。保留「约」和单位，不把已测距离改成未测距。极小图像连完整限定/字高也无法容纳时省略整条文字，不缩小系统字号；检测边界与原有详情规则保留。
- 背景 alpha 从 215 调整为 235，颜色保持；需要在原生 Canvas 的白/黑相机底色上核对灰黄红标签对比度。
- 排版与字形度量只在新结果或几何改变时准备，重复绘制仍复用 Entry；不改变识别结果、模型类别、分数、提醒阈值和任何帧/分析截止。

## 验证范围

原生标签矩阵计划覆盖三档字号、三种宽度、80 类灰/黄标签及测距标签，共 1449 组；另有留黑边四角的完整限定 72 组及极小图像 9 组。使用同上下文 TextView 的 11sp 作为平台转换参考，并检查字形与背景的实际边界；生成 18 张字体/宽度/测距样例与结构化字段。额外对三档字号、三种风险、白/黑底色共 18 组读取实际 Canvas 像素，按 4.5:1 门槛检查。原蒙版虚线、缓存复用、缩放与清除回归保留。

对比度门槛参照 [WCAG 2.2 普通文本 4.5:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，按实际软件像素与文字颜色计算；不能据此宣称真实屏幕在所有环境下达到相同可读性。

本地 146 项 JVM 测试无失败，Lint 0 错误 / 22 警告，应用与原生测试 APK 构建通过，产品表面与 v0.4.22 发布元数据检查通过。云端矩阵与截图尚待实际运行和复核。

首个候选 `cd4e1b6` 的 [41048695368](https://github.com/cyanrbt/walkbuddy/actions/runs/41048695368) 中，API 35/36 首次均通过全部九项探针；两个原始附件已下载并按服务端 SHA-256 核对。每套标签矩阵 1530 组、对比度 18 组通过，最低对比度分别为 5.0551 / 5.0423。截图复核发现 96dp、150%/200% 字号下，限定后可能仅剩分隔符或省略号，没有对象字符；虽满足完整限定与边界检查，仍会造成阅读负担。后续候选将此时的标签收为完整限定本身，保留仍有对象字符的有效缩略，并给全部限定用例补充检查；不把首轮成功改写为失败。

这是 Android 软件布局和对比度检查，样例使用构造检测结果，不代表真实物体或深度识别能力；目标设备、OEM 字体与 TalkBack 仍需实测。

矩阵检查每个标签的字形与画面边界，不证明密集多目标之间没有相互遮挡；多标签的位置冲突仍需后续专项排版。取景标签的省略不修改原检测输出和已有详情内容。
