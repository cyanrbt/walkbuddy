# 2026-10-30 检测故障时保留实时预览

此前模型初始化失败或分析超过 1500ms，会与相机画面过期一起进入预览不可用，关闭仍在更新的相机。正在验证的改动让可选检测失败时停止检测、声音、振动与旧结果，并在采集和显示仍新鲜时保留实时预览；用户可继续以小窗看画面，展开后主动重新勾选检测。

参考 Android [CameraX 分析背压说明](https://developer.android.com/media/camera/camerax/analyze)：耗时分析可以与其它相机用途保持独立，阻塞分析会影响预览。本项目继续使用 Camera2、现有唯一 worker 和固定模型；这里采用职责分离的思路，没有迁移相机库或加入 ML Kit。该改动改善故障后的可用性，不宣称模型推理变快或识别精度提高。

## 行为与时效

- 只有 LIVE 且采集/显示均在 1200ms 内新鲜时，1500ms 分析截止才停止检测；相机或显示同时过期时优先完整停止预览。摄像头权限撤回、锁屏、离开屏幕、黑画面与无效采集时间戳仍按原规则停止。
- 检测暂停立即取消原 Ticket，关闭检测与声音开关、清空候选/深度反馈、旧提醒与待朗读状态、取消振动并停止提示音；native 返回后的旧结果不得恢复反馈。没有延长分析截止、重置活动 Ticket 或自动重新开启检测。
- 已进入的 native 调用继续由唯一 worker 持有其帧，在返回后释放帧/模型；停止入口不等待 native。禁止关闭正在使用的模型、提前 recycle 活动帧或为重试创建并行 native worker。
- 完整预览显示“仅预览”及“检测已停止 · 仅看画面”，详情写明超时/失败并提示重新勾选；小窗显示两行“未检测 / 仅预览”，保持 200% 字体和窄窗含义可见。警示使用 polite live region；声音保持关闭，重新检测也不自动开启声音。
- 原基础模型、全部 80 类、标签顺序、风险阈值、500ms 取样间隔、1000ms 帧/结果期限、1200ms 相机心跳、1500ms 分析截止及 5000ms 相机启动截止均保持。SessionState 原严格过期检查保留，界面控制器在处理相机事件前按 PreviewHealth 区分故障范围。

## 验证

本地 146 项 JVM 测试通过，包含原 SessionState/CameraFrames/InferenceWorker 严格截止与所有权测试，以及新增六项检测/相机故障优先级、精确边界和启动截止测试。Lint 为 0 错误、22 警告，应用与 Android 测试包构建通过；产品界面和八项 CI 报告测试通过。新出现的 Gradle 更新提示未通过更换工具链消除。

原生 PiP 探针在现有真实模型回归之外增加受控故障：模型工厂抛错；另一 worker 阻塞在 detect 中，在真实相机继续更新时注入分析已超过 1500ms。检查相机与纹理身份不变、检测/声音/反馈清除、活动 Bitmap 未提前回收、进入小窗仍保留警示、释放阻塞后模型关闭且旧结果被丢弃、展开后仍未检测，最后由用户操作路径重新开启实际模型。故障注入截图不代表实际物体识别或真实道路异常。

布局检查在原 30 配置 / 120 正常状态之外，追加每配置的完整故障警示和 96×128 小窗警示，覆盖 100%/150%/200% 字体和日夜模式。云端实际运行、截图核对与发布附件结果在完成后补记。尚无 Find X8 Ultra、系统朗读或 AR 深度实机验收；旧的窗口输入及 native 性能根因仍未定位。
