# 密集目标标签排版

v0.4.22 已处理单标签字号、字形边界和对比度，但每个标签仍独立摆放，不能保证多目标之间可读。当前先增加 camera-free 原生截图基线：三档字号、三种宽度及同排、混合风险、31 个密集目标、留黑边四角四种构造场景，共 36 组。记录真实文字边界、可见数量和相交对数，不把基线采集通过当作已解决遮挡。

后续排版会参考 [Lookout 设计团队对清晰度的强调](https://design.google/library/google-lookout-design-accessibility)和 [Apple 相机设计中减少取景干扰的原则](https://developer.apple.com/design/human-interface-guidelines/camera-control)，优先重要信息并保留目标附近的对应关系。这是本项目的具体排版选择，不声称上述产品使用相同算法，也不引入其服务。

## 排版与绘制

- 红色近障碍、黄色关注、灰色候选依次占用空间；同级按有限距离、分数及稳定名称/坐标排序。只排序排版索引，不重排检测输出或改变检测数量、风险、提醒与时效。
- 在对象上下边缘，按左、右、中对齐尝试最多 12 个局部位置，保持 2dp 画面边距和标签间距。用短连接线指向相应边缘；无可用位置时省略文字，保留原轮廓与检测详情，不缩小用户字号，不承诺全部名称同时出现。
- 按全部填充 → 全部轮廓 → 短连接线 → 全部文字绘制，防止后续目标的蒙版/边线覆盖已绘文字。排版与字体度量只随新快照或几何变化发生；重复 show 仍复用 Entry。输入换序稳定不等于没有追踪的跨帧稳定。

本地 152 项 JVM 测试无失败，Lint 0 错误 / 22 警告，应用与原生测试包构建通过。6 项新回归含 256 组随机场景，每组 37 目标（基础最多 25 + 深度最多 12），验证间距、画面边界、邻近对象边缘及换序一致。原生修正矩阵仍为 36 组，追加完整限定、近障碍优先和缓存检查；另外 3 组逐像素对照验证后绘全图蒙版不改变标签像素。

各 36 组矩阵零相交、2dp 间距、边界、限定、近风险优先、换序稳定和缓存复用均通过。另有 3 组后绘全图蒙版的标签区域逐像素对照通过；原 1530 组单标签/字体与 18 组对比度回归保留。独立重算两套全部可见标签矩形，确认零相交和间距；九项原始 PASS 齐全，没有 FAIL、缺失探针或 ANR 观察。[修正后 JSON](crowd-native-2026-10-30.json)保存全部字段和来源。

实际查看 API 36 的 200% / 320dp 同排与密集图、96dp 近障碍、160dp 留黑边及蒙版覆盖图：[截图对照](../design/v0.4.23/README.md)。混合风险/31 同处目标在 200% 时，96/160/320dp 分别显示 1/2/3 个标签，近障碍始终保留；省略的是文字，全部构造检测对应的 Entry 和轮廓仍保留。不将零相交解释为所有标签同时可见，也不推断真实识别或跨帧追踪收益。
