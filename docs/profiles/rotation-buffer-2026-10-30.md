# 旋转移出主线程与缓冲复用

[Android 15/16 原生检查 41007311492](https://github.com/cyanrbt/walkbuddy/actions/runs/41007311492) 两套 API 首次全部通过，源码 `0aa8610`。原始逐项记录：[API 35](rotation-buffer-2026-10-30-api35.json)、[API 36](rotation-buffer-2026-10-30-api36.json)。已下载两套原始证据，核对每套四种传感器方向 × 四种显示方向 × 两种画幅，32 组无缺项。

| 显示方向 | v0.4.16 每帧主线程位图分配 | v0.4.17 每帧主线程位图分配 | v0.4.17 worker 旋转缓冲 |
| --- | ---: | ---: | --- |
| 0° | 300KiB | 300KiB | 不创建 |
| 90° / 180° / 270° | 600KiB | 300KiB | 首次分配 300KiB，容量内复用，关闭识别器时释放 |

范围为当前 640×480 相机流的 320×240 / 240×320 分析采样，ARGB_8888 逻辑位图分配。输入画布、RGB 字节、原始采样、解释器及其他堆内存不在此表内；旋转缓冲在识别期间保留，因此不能称为总内存或峰值内存减半。0° 没有对应的分配减少。

每套 API 的 56 组输入字节与冻结旧路径完全一致，覆盖所有方向、透明像素、不同密度、连续换形和消费位置；模型 16 组全部 151 个输出值与旧旋转/数组输出路径在 1e-6 内一致，原有单/双线程四组输出对照保留。旋转缓冲在容量内保持同一位图实例，关闭后 recycled。真实 TextureView 的 32 组输入字节同样完全一致，原有方向标记、圆形比例与显示检查保留；完整相机、实际模型和两轮 PiP 均通过。

首次尝试单次绘制合并旋转与缩放时，137×59 / 90° 的边缘像素不同；第二次调整矩形仍不同。因此最终实现保留旧绘制顺序，通过 worker 缓冲复用减少分配，并将旋转移出主线程。未放宽像素、帧时效或风险确认要求。

JSON 保留了旧完整画幅读回与新天然采样的短计时。这两项工作范围不同，新计时不含 worker 旋转，不能据此比较 v0.4.16 与 v0.4.17 的端到端速度。这里证明的是限定场景的输入/输出一致、方向、缓冲复用和位图分配；实体设备帧率、温升、耗电及此前间歇性分析超时仍待测量和排查。
