# v0.4.33 默认仅预览状态

## 问题与选择

v0.4.32 的相机已实时但检测默认关闭时，完整页仍标「实时」，进入小窗后隐藏开关，也没有「未检测」标识。已有「未检测 / 仅预览」提示只在检测故障或手动暂停的 notice 标志存在时显示。默认状态与这些停止状态都没有检测，表达却不同。

参考 [Lookout 的相机开关与模式说明](https://support.google.com/accessibility/android/answer/9031274)对当前能力作明确区分；[Android PiP 文档](https://developer.android.com/develop/ui/views/picture-in-picture)要求小窗隐藏完整交互界面。本项目据此保留必要的当前状态：完整页检测关闭时标题为「仅预览」，小窗内无论是否曾经故障，都显示既有「未检测 / 仅预览」文字。此为本项目的设计判断，不声称复制了 Lookout 界面或能力。

默认完整页不重复显示画面内提示，原 checkbox 与详情保持。检测故障/手动暂停的 notice 在完整页继续显示；检测开启时撤下仅预览提示。过期、启动及停止的状态优先，已有相机截止不改变。小窗里当前仅预览提示优先于可选深度/姿势文字；姿势传感器回调遵循同一规则，避免在相邻渲染间反复显隐。

| 当前情况 | 完整页标题 | 画面内仅预览提示 |
| --- | --- | --- |
| 相机启动中 | 启动中 | 无；保留启动遮挡 |
| 相机实时、检测关闭、没有暂停 notice | 仅预览 | 完整页隐藏；小窗显示「未检测 / 仅预览」 |
| 相机实时、检测关闭、有故障或手动暂停 notice | 仅预览 | 完整页和小窗均保留原提示 |
| 相机实时、检测开启 | 实时 | 撤下仅预览提示；准备/结果文字继续单独显示 |
| 已停止、故障或画面失效 | 已停下/故障恢复内容 | 不保留健康仅预览状态，画面遮挡及停止按原规则 |

## 验证方法

- 六项纯 JVM 检查覆盖首会话默认关闭、展开、既有暂停提示、重新开启、启动/停止/故障和已过期 LIVE 阶段。显示规则只读传入状态，不开启任何功能。
- 30 配置布局检查实际产品控件：默认完整标题单行，检测/声音与关闭详情仍在初始视口，96×128 小窗文字完整、polite live region 保持、可选文字不挤占；重复渲染保持文字对象，开启与展开后提示清除。此处验证控件元数据与文本绑定，不代替 TalkBack 实际朗读。
- 实际虚拟 Camera2/Activity 检查默认完整页、第一次真实 PiP、息屏后主动重开，检测开启/关闭，以及独立恢复流程四次重新进入小窗的提示。复用既有进入/恢复流程，不降低触摸/帧/分析门槛；默认检测、声音继续关闭，没有加载或提示请求由显示规则触发。
- 两套原生附件中的截图将分别注明静态布局与真实虚拟相机/系统小窗。APK 需核验新状态实现存在，原生断言与样例图片不进入主包，固定签名和版本保持。

最终 0.4.33 / 45 完整 224 项 JVM 为 0 失败 / 错误 / 跳过；Lint 0 错误 / 22 警告，应用与原生测试包构建、发布元数据、产品表面和差异格式通过。[本地 JSON](preview-only-default-2026-10-31.json)保留新状态用例及源文件摘要。候选与正式发布结果见后文。设备可读性、实际朗读、厂商小窗与真实 AR 仍待验收，不把 UI 变化当作检测准确率或历史显示停顿根因修复。
