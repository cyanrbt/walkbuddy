# 异步亮度读取候选

此前[系统轨迹](preview-system-trace-2026-10-31.md)中存在亮度读回主消息约 294.639ms、主线程 CPU 约 0.226ms 的样例。冻结 Canvas、虚拟 Camera2 与 EGL 的 [Surface 原型](surface-copy-2026-10-31.md)已在 API 26/35/36 逐像素通过。本轮将产品亮度检查迁到专用线程；这不足以证明历史 1246ms 停顿根因或实体性能改善，PixelCopy 仍可能与共享 RenderThread 竞争。

## 请求与截止

每个进程只有一个在途请求；主线程拥有观察与代次，专用线程执行 PixelCopy 调用、读取 192 个像素并求和。Android 8 的 API 实际同步，因此调用也必须离开主线程。源仍为 TextureView 的 SurfaceTexture 包装，目标 ARGB_8888、16×12、RGB 总和小于 1728 为暗；复制前清空。

原观测时间不因回调刷新，下一次检查与上一次提交的观测帧间隔至少 1000ms。等待全局空位、主线程排队、worker 排队和复制共用最早到期帧的 1000ms 截止，后续新帧不得延长；既有 100ms 看门狗和交付时均检查。错误或超时停止预览，无自动重启；采集/显示 1200ms 与模型/分析截止不变，模型 getBitmap 仍走原路径。

关闭清空监听器并退休票据；在途位图仅在实际复制回调后释放。全局空位也只在实际回调后归还，新会话不能积压更多原生请求。回调使用独立主线程 Handler，避免停止 Activity 的工作队列时顺带丢失清理。诊断只保留不可变标量，分别表示 WAITING/QUEUED/COPYING/DELIVERING/FINISHED、排队/墙钟/调用与像素 CPU/交付耗时和状态码。

## 本地与原生验收范围

11 项纯 JVM 票据测试覆盖单飞、固定最早截止、恰好 1000ms 过期、等待后不压缩下一周期、代次/重复回调与时钟倒退；两项问题信息回归覆盖独立阶段、冻结首因、未知/零时间、失败状态和恢复。完整本地结果见 [JSON](brightness-async-local-2026-10-31.json)。

新增原生组件探针检查 19 组 RGB/阈值/透明/部分与空复制/错误，以及过期、停止后延迟释放和新会话排他性；实际冻结 Surface、Camera2 和 EGL 另严格对照旧 TextureView 像素。真实 PreviewActivity 检查正常复用、受控错误停止及手动重新开启，保留原十项检查。旧 BrightnessSampler 移到测试包，旧受控微基准明确只是 v0.4.37 参考，不代表新异步实现性能。当前云端候选待触发，不能把编译通过写成原生通过。
