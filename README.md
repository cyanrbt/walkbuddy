# WalkBuddy

白天步行时，把后置摄像头留在系统画中画里，切到别的应用后继续看实时画面。这是一个 Android 学习原型，当前开发版本 **0.4.23**（versionCode 35），发布验证进行中。

它多留一个画面，并提供基础物体识别和实验性的空间障碍检测。空间检测按深度占用判断前方是否可能受阻，无需先认识物体名称。路还是要自己看。不要在马路、楼梯或骑行时靠它决定下一步。

## 怎么用

1. 首页按「三步开始」：允许摄像头 → 打开预览确认取景 → 以小窗观察。首次点「允许相机并预览」后，授权成功会接着打开预览；拒绝则留在首页。不需要悬浮窗或通知授权。
2. 先站着确认镜头方向。手机自然握在手里时，后置镜头经常朝向地面。
3. 确认取景后，点「以小窗观察」。拖动、缩放和返回完整界面由系统画中画管理，具体操作随系统版本变化。
4. 首页固定显示主要操作；已有预览时控制区放到顶部，减少右下角系统小窗遮挡按钮。点「返回预览」展开已有画面，点旁边的「停止」结束观察。也可用小窗菜单或完整预览页停止。

- 完整预览页先显示「检测」「声音」勾选开关，每次打开都默认关闭。声音只在检测开启后可用；下方详情先显示“未测距”或估算距离，再显示对象和位置。
- 取景标签跟随系统字号，文字背景按实际字形撑开。窄小窗优先保留完整的「未测距」或距离；空间不足时省略对象名称，测距可显示为「约0.7米」。极小画面容纳不了整行时不画残缺标签，字号保持用户设置。
- 多目标标签在各自目标边缘附近避让，优先显示红色近障碍与黄色关注。空间不足时省略部分标签，轮廓与提醒保留；可展开完整预览获得更多显示空间。标签最后绘制，避免其它轮廓或填充盖住文字。
- 正在使用完整预览取景时保持亮屏，无需反复点屏幕；进入小窗、失去焦点、停止或故障后释放亮屏。小窗是否息屏按前台应用与系统设置决定；电源键锁屏仍会停止相机。
- 锁屏、关掉小窗，或预览页完全离开屏幕时，会释放摄像头并停止提醒。回到预览页后要自己重新打开。
- 应用不会自动进入画中画。在完整预览里直接按 Home 会停掉相机。先点「以小窗观察」。
- 首页能查看这台设备是否支持画中画，并打开系统设置。不支持、被关掉或进入失败时，画面留在应用内，并给出设置入口。
- 首页进度按实际体验记录：出现实时画面后才完成「预览」，成功进入系统画中画后才完成「小窗」。小窗不可用时仍可在应用内观察；从系统权限设置返回后需自己点开预览。
- 检测加载、推理失败或超时时，若相机画面仍实时，自动关闭检测与提醒并保留画面。完整界面显示「仅预览」，小窗持续显示「未检测 / 仅预览」；展开后可重新勾选检测，声音保持关闭。
- 开启检测的小窗菜单增加「关闭检测」，直接停止检测、声音和振动并保留实时画面；关闭后显示「未检测 / 仅预览」，菜单保留「停止」以结束相机。重新开启检测需展开后主动勾选，声音保持关闭；具体菜单容量由系统决定。
- 相机或显示画面过期、锁屏、离屏时仍会停止相机。缺权限可直接前往设置，增强失败可先用基础画面；设置返回和切换中断后都需主动重新开启。声音开关只控制提示音，系统朗读单独设置；“最近提醒”与持续更新的检测详情分开显示。

## 打开识别之后

提供两种模式，每次开启预览后检测与提示音默认关闭：

- **基础模式**：本地 EfficientDet Lite0 显示其全部 80 类候选，移除旧的八类筛选。灰色角框表示捕获到目标；中央关注区内、分数至少 0.5 的目标连续确认后变黄并振动，标注「未测距」。基础模式不会变红。全部 80 个有效类别使用中文名称，见[类别表](docs/识别类别.md)。
- **空间检测（实验）**：点「空间增强：已关闭」，应用自动检查 AR 服务；缺失时由服务安装流程引导，启动会话后再确认 Depth API 支持。不支持时仍可使用基础模式。无需自己判断有没有安装 AR 服务。

启用空间检测后，按预览页四步引导操作：服务 → 地面 → 深度 → 提示。增强开启后基础模型仍持续工作；深度未就绪也保留基础框和提醒。切换增强保留检测/声音开关状态。空间部分以地面、深度和前方通行范围检测空间占用，茶几、箱子、路障无需在类别清单里。该能力依赖深度质量，**尚未完成 Find X8 Ultra 实机验收与阈值标定**。

| 显示 | 含义 |
| --- | --- |
| 灰色 | 捕获到目标或深度区域；不代表安全 |
| 黄色 | 基础框：画面中央目标连续确认，标注「未测距」；深度轮廓：约 2 米以内的通行范围障碍 |
| 红色 | 连续观测到约 0.9 米以内的障碍，需要及时注意 |

距离阈值和约 0.8 米宽通行范围是待实机标定的实验参数，不是碰撞概率；标定步骤见 [深度阈值标定](docs/深度阈值标定.md)。彩色轮廓来自有效深度区域，可能粗糙、断裂或合并多个物体，不是像素级物体分割。深度不足或地面未确认时暂停测距分级，基础画面关注提醒继续；测不到不等于可通行。

竖屏胸前持机明显朝地面/天空时会提示调整姿势。坑洞、下台阶、玻璃、细杆、遮挡和低纹理表面仍可能漏检；落差检测为实验能力，阈值未标定，不宣称覆盖所有步行风险。未直接读取厂商激光对焦传感器。

本应用不保存或上传画面，安装包没有网络权限。可选增强功能由 Google Play 服务 AR 提供；服务安装、更新及数据处理遵循 Google 隐私政策，启用前有说明与链接。

## 安装

当前 [v0.4.22 APK](https://github.com/cyanrbt/walkbuddy/releases/download/v0.4.22/Walk-Buddy-v0.4.22-arm64-debug.apk) 已通过 [发布构建](https://github.com/cyanrbt/walkbuddy/actions/runs/41052842543)，本次发布的 Android 15/16 检查和固定签名 APK 作业均首次成功。已实际下载核验版本、固定签名、模型、中文表和 11sp 标签资源；[验证记录](docs/验证结果.md)含完整摘要和模拟器/实机范围，此前锁屏输入失败与本次系统输入就绪修正的证据均保留。

Actions 中 `Release APK` 表示标签发布，`Android UI checks` 表示模拟器检查；检查红叉的具体原因、输入窗口就绪修正和历史问题的因果边界见 [CI 失败核对](docs/profiles/ci-failures-2026-10-30.md)。纯文档或模型研究改动仅运行相关检查，标签发布仍须通过两套 Android 检查后才能生成安装包。

推送 `v` 开头的标签后，GitHub Actions 会构建 **arm64** 调试包，并挂到 [Releases](https://github.com/cyanrbt/walkbuddy/releases)。文件名是 `Walk-Buddy-<标签>-arm64-debug.apk`，只含 arm64-v8a，最低 Android 8。同一页上的 Source code 压缩包是源码，不是可安装的应用。

从 0.3.2 起，包名是 `com.cyanrbt.walkbuddy`。系统把它当成新应用，可以和旧包 `cn.study.window` 同时安装，旧应用里的设置不会迁过来。

覆盖安装要满足三点：包名相同、签名证书相同、versionCode 不低于已装版本。只改 `versionName` 或标签不会抬高 versionCode。装不上时先核对这三项。卸载会清掉这个包名下的应用数据。

已核对、且证书彼此不同的历史包不能互相覆盖：

| v0.3.0 | 8 | `1c4b3a2ce0652541d28b2ae2bb152a684974b881a4028f9ab4e90b06a0edad9a` |

## 本地构建

需要 JDK 17，以及 Android SDK 36（platforms、build-tools 36.0.0、platform-tools）。在项目根目录写 `local.properties`：

```
sdk.dir=/绝对路径/android-sdk
```

```sh
python3 scripts/check_model.py
./gradlew assembleDebug testDebugUnitTest lintDebug
```

调试包在 `app/build/outputs/apk/debug/app-debug.apk`。四 ABI 包用 `./gradlew assembleDebug -PuniversalApk`。

固定组合是 Java 17、Gradle 8.13、Android Gradle Plugin 8.10.1、LiteRT 1.4.0、ARCore 1.56.0。第一次构建会下载依赖。本应用不申请网络权限；可选 AR 服务是独立组件。

## 发布

仓库 Actions Secret `DEBUG_KEYSTORE_BASE64` 里要有固定签名密钥库的 base64。密码是 `android`，别名是 `androiddebugkey`。原始密钥另外备份，不要提交进仓库，也不要传到 Release。私钥不能从 APK 里还原。

工作流只使用这份 Secret。密钥缺失或无效时，发布会停下来，不会改用缓存，也不会临时生成一把新钥匙。别名和密码相同，不代表证书相同。换了证书之后，已安装的用户需要卸载再装，之后才能继续覆盖升级。

每次发布前递增 `app/build.gradle` 里的 `versionCode` 和 `versionName`，添加 `docs/releases/v<版本>.md`，并保持 `applicationId` 为 `com.cyanrbt.walkbuddy`。CI 校验标签与版本一致，并使用该版本的说明发布。重大更新验证通过后提交、推送并创建新的 `v*` 标签，随后确认对应 Actions 成功且 Release 页面上的 APK 附件可以下载。
