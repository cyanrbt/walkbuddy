# WalkBuddy

白天步行时，把后置摄像头留在系统画中画里，切到别的应用后继续看实时画面。这是一个 Android 学习原型，当前版本 **0.4.38**（versionCode 50），已发布固定签名安装包。

开发中的 **0.4.39**（versionCode 51）调整首帧就绪：有效画面校验完成前保留启动遮罩，小窗、检测和首页首次进度在校验后启用。本地 270 项 JVM、Lint 和双 APK 编译通过，云端原生验证及发布尚待完成。[改动与验证进展](docs/profiles/preview-readiness-2026-10-31.md)。

它多留一个画面，并提供基础物体识别和实验性的空间障碍检测。空间检测按深度占用判断前方是否可能受阻，无需先认识物体名称。路还是要自己看。不要在马路、楼梯或骑行时靠它决定下一步。

## 怎么用

1. 首页按「三步开始」：允许摄像头 → 打开预览确认取景 → 以小窗观察。首次点「允许相机并预览」后，授权成功会接着打开预览；拒绝则留在首页。不需要悬浮窗或通知授权。
2. 先站着确认镜头方向。手机自然握在手里时，后置镜头经常朝向地面。
3. 确认取景后，点「以小窗观察」。拖动、缩放和返回完整界面由系统画中画管理，具体操作随系统版本变化。
4. 首页固定显示主要操作；已有预览时控制区放到顶部，减少右下角系统小窗遮挡按钮。点「返回预览」展开已有画面，点旁边的「停止」结束观察。也可用小窗菜单或完整预览页停止。

- 完整预览页先显示「检测」「提示音」勾选开关，每次打开都默认关闭。提示音只在检测开启后可用；下方详情先显示“未测距”或估算距离，再显示对象和位置。
- 基础识别和空间检测共用提醒间隔。某个提醒暂时被间隔限制时，新的有效结果仍可在允许时发出；目标消失、降级或停止后不回放旧提醒。红色升级沿用较短间隔，重复提醒仍限频。
- 振动提醒开启时，黄色确认提醒使用单次触觉，红色使用双次；目标消失或风险降级会取消尚未完成的振动。可在图例下单独关闭「振动提醒」，保留检测画面和其它反馈设置；重新开启不补播旧提示。振动选择会记住，图例与问题信息同步反映状态，实际振感仍受设备与系统设置影响。
- 取景标签跟随系统字号，文字背景按实际字形撑开。窄小窗优先保留完整的「未测距」或距离；空间不足时省略对象名称，测距可显示为「约0.7米」。极小画面容纳不了整行时不画残缺标签，字号保持用户设置。
- 多目标标签在各自目标边缘附近避让，优先显示红色近障碍与黄色关注。空间不足时省略部分标签，轮廓与提醒保留；可展开完整预览获得更多显示空间。标签最后绘制，避免其它轮廓或填充盖住文字。
- 连续结果能明确对应时，标签优先维持上次的局部边缘位置，减少分数轻微互换带来的跳换；框、文字和距离仍随当前结果更新。匹配不明确、风险变化、状态过期、停止或画面几何改变后重新排版。
- 重叠形状按灰、黄、红的层级绘制，红色近障碍轮廓最后呈现，减少检测列表换序时被较低风险边线覆盖的问题。文字、虚线及原提醒语义保持。
- 正在使用完整预览取景时保持亮屏，无需反复点屏幕；进入小窗、失去焦点、停止或故障后释放亮屏。小窗是否息屏按前台应用与系统设置决定；电源键锁屏仍会停止相机。
- 锁屏、关掉小窗，或预览页完全离开屏幕时，会释放摄像头并停止提醒。回到预览页后要自己重新打开。
- 遇到预览停止或检测故障，可在控制区点「复制问题信息」，将版本、设备型号、首个原因和当时的时序复制后自行粘贴反馈。页面重建会保留并标记旧记录；重新尝试预览后开始新记录，复制操作不打开相机。
- 应用不会自动进入画中画。在完整预览里直接按 Home 会停掉相机。先点「以小窗观察」。
- 小窗缩放动画的取景边界扣除黑边，并随布局、方向和展开后的相机区域更新；旋转和缩放沿用当前相机。实际动画流畅度受设备与系统影响。
- 首页能查看这台设备是否支持画中画，并打开系统设置。不支持、被关掉或进入失败时，画面留在应用内，并给出设置入口。
- 首页进度按实际体验记录：出现实时画面后才完成「预览」，成功进入系统画中画后才完成「小窗」。小窗不可用时仍可在应用内观察；从系统权限设置返回后需自己点开预览。
- 检测加载、推理失败或超时时，若相机画面仍实时，自动关闭检测与提醒并保留画面。完整界面显示「仅预览」，小窗持续显示「未检测 / 仅预览」；展开后可重新勾选检测，声音保持关闭。
- 开启检测的小窗菜单增加「关闭检测」，直接停止检测、声音和振动并保留实时画面；关闭后显示「未检测 / 仅预览」，菜单保留「停止」以结束相机。重新开启检测需展开后主动勾选，声音保持关闭；具体菜单容量由系统决定。
- 检测运行时，小窗菜单的第三个自定义位置可直接「打开提示音 / 关闭提示音」，保留相机、检测和振动选择；系统朗读单独设置。位置不足时优先保留停止相机、关闭检测，提示音仍可在完整页调整。横屏设置侧栏按完整开关标签宽度适配，保持系统字号。
- 相机或显示画面过期、锁屏、离屏时仍会停止相机。缺权限可直接前往设置，增强失败可先用基础画面；设置返回和切换中断后都需主动重新开启。声音开关只控制提示音，音频操作由独立线程执行，失败时关闭声音并保留检测和画面；系统朗读单独设置。“最近提醒”与持续更新的检测详情分开显示。
- 停止界面集中呈现原因、恢复说明与操作，收起不可用的设置；停止小窗显示「已停止 / 请展开」，展开恢复完整说明，仍需主动开启相机。[验证进展](docs/profiles/recovery-presentation-2026-10-31.md)。

## 打开识别之后

提供两种模式，每次开启预览后检测与提示音默认关闭：

- **基础模式**：本地 EfficientDet Lite0 显示其全部 80 类候选，移除旧的八类筛选。灰色角框表示捕获到目标；中央关注区内、分数至少 0.5 的目标连续确认后变黄，按振动设置提醒，标注「未测距」。基础模式不会变红。全部 80 个有效类别使用中文名称，见[类别表](docs/识别类别.md)。
- **空间检测（实验）**：点「空间增强：已关闭」，应用自动检查 AR 服务；缺失时由服务安装流程引导，启动会话后再确认 Depth API 支持。不支持时仍可使用基础模式。无需自己判断有没有安装 AR 服务。

启用空间检测后，按预览页四步引导操作：服务 → 地面 → 深度 → 提示。增强开启后基础模型仍持续工作；深度未就绪也保留基础框和提醒。切换增强保留检测/声音开关状态。空间部分以地面、深度和前方通行范围检测空间占用，茶几、箱子、路障无需在类别清单里。该能力依赖深度质量，**尚未完成 Find X8 Ultra 实机验收与阈值标定**。

| 显示 | 含义 |
| --- | --- |
| 灰色 | 捕获到目标或深度区域；不代表安全 |
| 黄色 | 基础框：画面中央目标连续确认，标注「未测距」；深度轮廓：约 2 米以内的通行范围障碍 |
| 红色 | 连续观测到约 0.9 米以内的障碍，需要及时注意 |

距离阈值和约 0.8 米宽通行范围是待实机标定的实验参数，不是碰撞概率；标定步骤见 [深度阈值标定](docs/深度阈值标定.md)。彩色轮廓来自有效深度区域，可能粗糙、断裂或合并多个物体，不是像素级物体分割。深度不足或地面未确认时暂停测距分级，基础画面关注提醒继续；测不到不等于可通行。

竖屏胸前持机明显朝地面/天空时会提示调整姿势。坑洞、下台阶、玻璃、细杆、遮挡和低纹理表面仍可能漏检；落差检测为实验能力，阈值未标定，不宣称覆盖所有步行风险。未直接读取厂商激光对焦传感器。

本应用不保存或上传画面，安装包没有网络权限。可选增强功能由 Google Play 服务 AR 提供；服务安装、更新及数据处理遵循 Google 隐私政策，启用前有说明与链接。

## 安装

当前 [v0.4.38 APK](https://github.com/cyanrbt/walkbuddy/releases/download/v0.4.38/Walk-Buddy-v0.4.38-arm64-debug.apk) 已通过[正式发布构建](https://github.com/cyanrbt/walkbuddy/actions/runs/41172338591)：Android 15/16 与 APK 三个作业均首次成功。实际安装包已完整下载，核对 0.4.38 / 50、原固定签名、ARM64、模型和文件摘要；两份正式 UI 附件也已核验并重放。[安装包记录](docs/profiles/apk-v0.4.38.json)与[正式原生结果](docs/profiles/brightness-v038-release-native-2026-10-31.json)保留。合入前的 259 项 JVM、三套像素、两套系统轨迹检查和六条原始轨迹重放通过；开发专项另有画面过期与输入/电源前提失败样本，按来源保留，不能用正式成功覆盖它们。

本轮在实际画面更新时，将 16×12 亮度复制与求和投递专用线程；默认仅预览不再额外排队主线程模型读回任务。整个进程最多一个未结束复制，旧 View 回调和停止后的结果不能影响新观察，缓冲待实际复制结束再释放。问题信息单独保存亮度等待、复制和交付阶段。超过 1000ms 的旧观测不启动新请求；新的异步等待从最早到期帧起最多 1200ms，采集/显示与模型的原有截止保持，错误或超时仍需主动重新开启。[本轮策略、原始失败与完整验收](docs/profiles/brightness-preview-budget-2026-10-31.md)分别记录，不宣称历史停顿根因解决或实体帧率、耗电改善。真实设备、TalkBack、AR 与道路仍待验收。

Actions 中 `Release APK` 表示标签发布，`Android UI checks` 表示普通模拟器检查，`Surface copy experiment` 和 `Preview system trace` 为开发专项。正式标签仍须通过两套 Android 检查后才能生成 APK；专项的红叉不等同于 APK 编译失败，正式发布成功也不等同于全部专项故障已解决。

目前仍保留一次采集/显示龄 1436/1420ms 的画面过期，根因待定位。另一次首页失焦已用原图、当前输入焦点与同设备时间线确认：Pixel Launcher 的无响应弹窗覆盖首页，且其 ANR 早于应用测试进程启动；这不解释前一次画面停顿或后续关屏。[本轮原始证据与范围](docs/profiles/surface-startup-trace-2026-10-31.md)。

为定位专项后的画面停顿，第一轮系统轨迹增加原有 Surface 专项及随后两次 APK 重新安装，再执行恢复；后两轮保留原恢复场景。首轮采证遗漏的相机授权准备已补齐，51 项工具测试通过；修订后的普通 UI 与系统轨迹均首次成功，四份附件和六条原始轨迹已实际核验重放。仍有一次首请求耗时 1134ms 的近截止样本，不能据成功称旧停顿已修复。这次只完善采证，不改变应用时效或已发布版本。[场景、失败保留和完整验证](docs/profiles/surface-startup-trace-2026-10-31.md)。

该 1134ms 样本进一步确认：回调等待窗口内，两核持续忙碌，RenderThread 约 724ms 处于可运行但未获 CPU 的状态；同进程复制区段约在请求返回 888ms 后才开始。现保留两核检查，增加受实际运行机容量限制的最多四核专项，并核验模拟器实际核数。57 项工具检查通过，四核两套专项及六条原始轨迹重放通过；两核普通 UI 一次恢复点击被系统暂停窗口拒收，单次同源码复验通过，首轮失败保留。当前四个流程终态成功，不能称九作业全部首次成功或历史停顿已修复。[时序图、原始调度数据与完整实验范围](docs/profiles/brightness-wait-2026-10-31.md)。

恢复触摸新增测试侧保护：只在系统日志精确证明 DOWN 因暂停而没有任何接收目标、且应用仍未启动时，允许在原就绪预算内重新准备一次；已送达或含糊的输入不重试。27 项规则检查、57 项工具检查及本地编译通过。云端首轮 8/9 作业成功，两套普通 UI 附件重放通过，各有七次真实恢复触摸启用保护，但未发生新拒收，不能称真实重试分支已验证。失败的两核 API 35 轨迹作业有 Pixel Launcher 无响应弹窗占据输入焦点，原始截图与三条失败轨迹均已核验并保留；仅该作业单次复验后成功，四个流程现均为成功，不能称九作业全部首次通过。[资格保护、证据与验证范围](docs/profiles/rejected-restore-down-2026-10-31.md)。

## 本地构建

需要 JDK 17，以及 Android SDK 36（platforms、build-tools 36.0.0、platform-tools）。在项目根目录写 `local.properties`：

```
sdk.dir=/绝对路径/android-sdk
```

```sh
python3 scripts/check_model.py
./gradlew assembleDebug testDebugUnitTest lintDebug
```

调试包在 `app/build/outputs/apk/debug/app-debug.apk`。四 ABI 包用 `./gradlew assembleDebug -PuniversalApk`。

固定组合是 Java 17、Gradle 8.13、Android Gradle Plugin 8.10.1、LiteRT 1.4.0、ARCore 1.56.0。第一次构建会下载依赖。本应用不申请网络权限；可选 AR 服务是独立组件。

## 发布

仓库 Actions Secret `DEBUG_KEYSTORE_BASE64` 里要有固定签名密钥库的 base64。密码是 `android`，别名是 `androiddebugkey`。原始密钥另外备份，不要提交进仓库，也不要传到 Release。私钥不能从 APK 里还原。

工作流只使用这份 Secret。密钥缺失或无效时，发布会停下来，不会改用缓存，也不会临时生成一把新钥匙。别名和密码相同，不代表证书相同。换了证书之后，已安装的用户需要卸载再装，之后才能继续覆盖升级。

每次发布前递增 `app/build.gradle` 里的 `versionCode` 和 `versionName`，添加 `docs/releases/v<版本>.md`，并保持 `applicationId` 为 `com.cyanrbt.walkbuddy`。CI 校验标签与版本一致，并使用该版本的说明发布。重大更新验证通过后提交、推送并创建新的 `v*` 标签，随后确认对应 Actions 成功且 Release 页面上的 APK 附件可以下载。
